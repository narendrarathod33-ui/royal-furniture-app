# Customization / Made to Order collection

- Entry: the second Home promotion replaces the former Everyday / fresh-find promotion. The first promotion uses an existing Dayana product photo; the new customization promotion uses the existing Rainbow Bed photo. Both use contain sizing. The kids promotion record, image, copy, sizing and category destination remain unchanged.
- Source of truth: the existing full `app/data/catalogData.ts` list, the same 1,360-entry catalog used by Browse. Eligibility requires an explicit Made to Order marker in its product description or labels. The current catalog has **134 qualifying entries**. Generic customization/size/fabric capabilities, external live detail fields, and guessed product types do not add items.
- Every qualifying catalog entry is available: no arbitrary result limit or size-family collapse removes individual entries. Virtualization only controls rendering, not membership.
- Filters: category (only categories with qualifying products), name/subcategory search, and numeric selling-price low/high sorting. Catalog order is the default. Empty state and Clear/Reset return to the complete qualifying list. Eligibility is reapplied before every filter/sort.
- Existing ProductCard, product details, saved items, size selection and cart callbacks are reused. Filter state lives in AppSession so opening a product and using Back preserves selection. The page has Back to home plus the normal Account, Cart and navigation controls.
- Customization is highlighted as the collection's proposition, not a new order configurator or an unconditional promise that every product supports every material/dimension. Copy asks shoppers to confirm custom requests, available options and lead times with the team.
- Verification: `npm run test:customization`, the updated Home/navigation suites, all regression tests, TypeScript and web export. Browser checks at 320/390/768/1280px include entry, count, bounds, sorting, product/Back state, empty search recovery and home return. Remote product images were blocked/unavailable during sandbox browser tests; local promotion/hero photos load. Physical native devices remain a follow-up check.
